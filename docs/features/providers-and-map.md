## Provider directory and details

[`ProvidersPage`](../../src/features/providers/pages/ProvidersPage.jsx) lists providers with server pagination, debounced search, status/date/category/specialist filters, and create or status actions gated by permission. [`providersService.js`](../../src/features/providers/services/providersService.js) sends those parameters to `GET /admin/providers`; create and update send multipart form data with bilingual names, category, optional specialist, contact fields, active state, and an optional logo. The provider lookup sends `SearchTrem` as spelled in source. Whether that spelling is accepted by the live API is not verified here.

[`ProviderDetailsPage`](../../src/features/providers/pages/ProviderDetailsPage.jsx) is shared by `/providers/new` and `/providers/:id`. It can present the main provider form and, for an existing provider, permission-filtered branches, services, packages, and renewals tabs. An edit request also checks `providers.update`. Route-level provider read permission alone does not expose every nested tab or action.

## Branches and provider services

The standalone [branches page](../../src/features/branches/pages/BranchesPage.jsx) renders the branch tab in read-only mode. The tab and its [service](../../src/features/branches/services/providerBranchesService.js) support provider-specific or all-provider lists, geographic filters, search, status, pagination, create/update, and activate/deactivate actions. The branch UI uses status values 0, 1, and 2 for all, active, and deactive. The service returns the response body unchanged while [the hooks](../../src/features/branches/hooks/useAllBranchesQuery.js) read top-level `items` and pagination fields; the actual response shape must be checked against the backend before assuming the list works.

[Provider services](../../src/features/providerServices/components/ProviderServicesTab.jsx) associate a provider with a catalog service and price, discount, special-offer, and active fields. [`providerServicesService.js`](../../src/features/providerServices/services/providerServicesService.js) uses a provider-scoped list, JSON create/update, a PATCH activation call, and a DELETE deactivation call. These are client request choices; backend effects are unverified.

## Packages

[`ProviderPackagesTab`](../../src/features/providerPackages/components/ProviderPackagesTab.jsx) lists paginated packages, displays price and discount information received from the API, and permission-gates create, edit, status, and delete controls. [The form](../../src/features/providerPackages/components/ProviderPackageFormModal.jsx) validates bilingual content, percentage and price, two images, and selected provider services, then converts values for [multipart create/update requests](../../src/features/providerPackages/services/providerPackagesService.js). On update, image fields are sent only when a new `File` is supplied. The detail request reads `data.data`; the list hook reads `data.data.items`. Successful mutations invalidate package Query keys. The actual backend price calculation and deletion semantics are not established by the front end.

## Contract renewals

For an existing provider, the **Renewals** tab uses the provider page's `providers.read` permission. [`ProviderRenewalsTab`](../../src/features/providerRenewals/components/ProviderRenewalsTab.jsx) displays renewal ID, contract start/end dates, broker name, and broker phone, with loading, empty, and retry states. Missing broker fields display "Not provided". The list starts at 15 rows per page and supports server pagination and page-size changes.

[`providerRenewalsService.js`](../../src/features/providerRenewals/services/providerRenewalsService.js) sends `GET /ProviderRenewalAdmin` with `ProviderId`, `PageNumber`, and `PageSize`, through the shared authenticated Axios client. [`useProviderRenewalsQuery`](../../src/features/providerRenewals/hooks/useProviderRenewalsQuery.js) reads the nested `data.items`, `data.totalCount`, and `data.totalPages` envelope and caches each provider/page/size separately. Requests run when the tab is mounted for an existing provider; switching providers resets pagination and does not show the previous provider's renewals. Application responses with `succeeded: false` are treated as errors.

Users with `providers.update` can choose **Add renewal**. [`ProviderRenewalFormModal`](../../src/features/providerRenewals/components/ProviderRenewalFormModal.jsx) uses the same shared `DatePicker` as price-list forms: dates display as `dd/mm/yyyy` and are sent as `YYYY-MM-DD` without a timezone conversion. Both dates are required and the end date must be on or after the start date. `POST /ProviderRenewalAdmin` sends JSON `{ startAt, endAt, providerId, brokerId }`; IDs are numbers and an unselected broker is `null`. Users with `brokers.read` can optionally select a broker using the existing paginated, searchable `/BrokerAdmin` service. Successful creation refreshes that provider's renewal queries and closes the form; failed creation keeps the entered values for retry. Saving disables the fields and blocks closing or submitting again.

Users with `providers.update` can choose **Edit dates** on a renewal. The same form pre-fills its dates from `contractStartAt` and `contractEndAt`, using `dd/mm/yyyy` for display and `YYYY-MM-DD` for requests. `PUT /ProviderRenewalAdmin/{id}` uses the renewal ID in the path and sends exactly `{ providerId, startAt, endAt }` as JSON. The broker selector is available during creation. Both dates and their order are validated before saving. Successful updates refresh that provider's renewal queries and close the form; failures retain the edited values and display an error for retry.

Each renewal's **View attachments** action opens [`ProviderAttachmentsModal`](../../src/features/providerAttachments/components/ProviderAttachmentsModal.jsx). [`providerAttachmentsService.js`](../../src/features/providerAttachments/services/providerAttachmentsService.js) sends `GET /ProviderAttachmentAdmin/renewals/{providerRenewalId}`, using the selected renewal's ID. The hook reads the `data` array and caches it separately for each renewal. The dialog loads on demand, shows attachment type and file format, and provides links to open the API's file URLs in a new tab. It supports loading, empty, and retry states, and closes via its close button, Escape, or backdrop.

Users with `providers.update` can upload files from the attachments dialog. The form starts with one row containing an attachment type dropdown and a single-file input. **Add Attachment** appends a blank row, and each row can be removed. Types are Contract (1), Additional contract (2), Price list (3), Commercial register (4), Tax card (5), or Other (6). Each row requires one type and one file; image/PDF/Excel `.xls`/`.xlsx` format errors and the 5 MB per-file limit are validated and displayed beside that row's file input. `POST /ProviderAttachmentAdmin/{providerRenewalId}` sends multipart form data with matching repeated `AttachmentTypes` and `Files` entries in row order. Successful uploads refresh only that renewal's attachment list and reset the form to one blank row; failed uploads retain the rows and show an error. Form controls and dialog dismissal are disabled while uploading.

Users with `providers.update` can also choose **Replace file** on an existing attachment. The inline form validates one replacement file using the same 5 MB and image/PDF/Excel rules, then sends `PUT /ProviderAttachmentAdmin/{id}` with a single multipart `File` field. The path ID is the attachment ID. Successful replacement refreshes that renewal's file list; failed replacement keeps the selected file and displays server errors for retry. Uploads, other replacement actions, and dialog dismissal are disabled while a replacement is pending.

Users with `providers.update` can choose **Delete** on an attachment and confirm within its row. `DELETE /ProviderAttachmentAdmin/{id}` uses the attachment ID in the path without a request body. Successful deletion refreshes only the current renewal's attachment list and shows a success message. An application or HTTP failure keeps the attachment and confirmation visible with an error for retry; deletion does not retry automatically. Creation, replacement, other delete actions, and dialog dismissal are disabled while deletion is pending.

## Map

[`ProviderMapPage`](../../src/features/provider-map/pages/ProviderMapPage.jsx) fetches provider/branch map data by provider category and can fetch client locations when the “Users” toggle is on. [`useProvidersMapQuery`](../../src/features/provider-map/hooks/useProvidersMapQuery.js) filters invalid Egypt coordinates, resolves governorates from local polygon data, and applies governorate and search filtering on the client. It builds branch markers and governorate/country bubbles. [`usecCientLocationsQuery`](../../src/features/provider-map/hooks/usecCientLocationsQuery.js) groups valid client coordinates into fixed 200-meter grid cells and aggregate bubbles. [`ProviderClusterMap`](../../src/features/provider-map/components/ProviderClusterMap.jsx) renders the Leaflet view. The presence or accuracy of live location data is backend-dependent.
