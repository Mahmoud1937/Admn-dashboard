## Dashboard, clients, and invoices

[`DashboardPage`](../../src/features/dashboard/pages/DashboardPage.jsx) combines summary cards and charts. [The dashboard service](../../src/features/dashboard/services/dashboardService.js) sends date-range parameters to `GET admin/dashboard` and grouping/year parameters to `GET admin/dashboard/chart`. Summary and chart filters are saved separately in browser `sessionStorage` by [`dashboardFilterSession.js`](../../src/shared/utils/dashboardFilterSession.js), and session changes clear them. The grouping codes in source are month 1, quarter 2, half-year 3, and year 4; server aggregation rules are unverified.

[`useClientsQuery`](../../src/features/clients/hooks/useClientsQuery.js) builds server list parameters for search, platform type, sex, card possession, optional pool source, and pagination. It computes `totalPages` from `totalCount` and page size because a source comment reports inconsistent backend `totalPages` values. [Client details](../../src/features/clients/pages/ClientDetailsPage.jsx) bring together the client record, family members, order history, and invoice preview/detail flows. [`clientsService.js`](../../src/features/clients/services/clientsService.js) sends a `PUT /ClientAdmin/block` request for block/unblock, but explicitly labels that method an assumption; the live backend contract remains unverified.

[`InvoicesPage`](../../src/features/invoices/pages/InvoicesPage.jsx) uses debounced search, draft/applied filters, server pagination, an invoice table, detail modal, timeline, and export. [`useInvoicesQuery`](../../src/features/invoices/hooks/useInvoicesQuery.js) converts filter dates to UTC day boundaries and sends client/provider/branch/status/payment filters. [`invoicesService.js`](../../src/features/invoices/services/invoicesService.js) reads list data from the response envelope and fetches approval history by order number. The page currently does not display its query error state. Client and invoice exports request Blobs; [export hooks](../../src/features/invoices/hooks/useExportInvoices.js) create downloadable `.xlsx` filenames. The returned file type and contents require backend verification.

## Tickets

[`TicketsPage`](../../src/features/tickets/pages/TicketsPage.jsx) shows a filtered, paginated ticket list with create and detail flows. [`ticketsService.js`](../../src/features/tickets/services/ticketsService.js) sends search, client, ticket type, provider, employee group, priority, and closed-state filters; create sends ticket metadata and description. Details come from `GET /admin/tickets/{id}`. [`TicketDetailsModal`](../../src/features/tickets/components/TicketDetailsModal.jsx) displays overview and timeline data and prevents editing when `isClosed` is true. [`ticketDetailsUtils.js`](../../src/features/tickets/utils/ticketDetailsUtils.js) constructs an update payload and maps known validation fields. The UI's status labels and priority options come from local constants; backend workflow transitions are not established here. Ticket types have their own CRUD screen and service.

## Card operations

[Card pools](../../src/features/cardPool/services/cardPoolService.js) support paginated searching and date filtering, pool creation with URL-encoded `count`, sold-card listing by pool, export, and delete. [Sold-card records](../../src/features/sold-card/services/cardSoldService.js) support creation by count or by card numbers with multipart payment proof, list, export, and delete. [Missed-card records](../../src/features/missedCard/services/cardMissedService.js) support list, create, and delete; source comments label missing type 0 as missed and 1 as damaged. [Card activation](../../src/features/cardActivtion/services/cardActivationService.js) is a listing of non-activated cards and an export request; the source contains no activation mutation. These descriptions refer to UI and HTTP calls, not to confirmed inventory or financial effects on the server.
